# 从 83 幅教材插图里挖出来的坑与改法（2026-11-24）

> 背景：用 ChemDraw 做《高等有机化学》83 幅插图，跨 12 轮迭代、多个模型分工（codex 画 / Gemini 审）。
> 下面每条都是**实测**出来的，不是推测；每条给出「症状 / 根因 / 建议改法（落到 skill 或 toolkit 的哪一层）」。
> 目标读者：继续维护 chemdraw skill 的 agent。

---

## P0-1 「回读 matched」不等于「渲染一致」——最容易漏的一层

**症状**：CDXML 解析回读 100% 对得上（原子数、键、字、符号全在），但把同一份 CDXML 用 ChemDraw 渲染出来，图里**少了一个元素**。

**根因**：回读只验证「XML 里有这个节点」，不验证「ChemDraw 会不会画这个节点」。两者不等价。

**建议**：
- 在校验层加一条硬规则：**产出 PNG 必须由 ChemDraw 渲染同一份 CDXML 得到**，并且做「渲染回归」——改前/改后各渲一次，逐元素比对墨迹包围盒。
- 若保留自建渲染器，必须标注 PNG 的来源（`render_source: chemdraw|builtin|patch`），三种来源**不可混用**在同一套图里。

## P0-2 `<graphic GraphicType="Oval">` 这类装饰圆，ChemDraw 不渲染

**症状**：fig1-2 的甲基自由基点，CDXML 里是 `<graphic GraphicType="Oval" OvalType="Circle"/>`；用 ChemDraw 重渲染后**点直接消失**（HEAD 版本和多种变体都试过）。

**根因**：这个点是上游自建渲染器画的；ChemDraw 对该 graphic 不落笔。

**建议**：
- 自由基点用 **原子属性**：`<n Radical="doublet"/>`（ChemDraw 自动摆点、位置由排版决定，永不压线）。
- 电荷用 `GraphicType="Symbol"` + `SymbolType="CirclePlus|CircleMinus"`，不要用椭圆+文字模拟。
- 在 skill 里列一张**「原生对象白名单」**：原子/键/箭头(`<arrow>`)/括号(`<bracket>`)/符号(`<graphic SymbolType=...>`)/轨道；**裸线+文字画出来的“图形”一律禁止**，因为 ChemDraw 化学感知不到、回读也不报错。

## P0-3 用文本字形当“点”不可靠

**症状**：想在 C 右上角加一个自由基点，试了四种写法：
- Arial `·` → 渲染成**方块**（缺字形，tofu）
- SimSun `·` (size 20) → 尺寸失控，直接压在 C 上
- Arial `•` / Times `•` → 能出圆点，但字号与基线随字体走，跨平台不可控

**建议**：不要用文本点。要“点”就用 P0-2 的原生属性/符号。

## P0-4 PNG 导出的分辨率：`export_image` 与 `Preferences.PNGResolution` 是两套

**实测**：
- MCP `chemdraw_export_image(dpi=300|600|1200)` → **永远 820×388 @144dpi**（dpi 参数无效）
- COM `app.Preferences.PNGResolution` + `Document.SaveAs("x.png")` → **有效**：
  - 300 → 3417×1613 px
  - 600 → 6834×3224 px

**建议**：
- 提供 `render_cdxml.py`（本次已写）作为标准出图入口；把分辨率当参数而不是靠 MCP。
- 记一条：`SaveAs` 支持 `cdxml / svg / emf / tif / eps / png`，**不支持 pdf**（会静默无产物）。

## P1-1 标记类元素要有「落点净空」校验

**症状**：自由基点被摆在 C–H 键上，压住键线；肉眼在低分辨率下看不出。

**建议**：加一个机检 `scan_mark_collisions.py`（本次已写）：
- 取所有小标记（`Oval`/`Symbol`，半径 ≤1.6 单位）
- 算到所有 `Line` 线段与文字锚点的距离
- 阈值：到键线 ≥ 半径+0.6；到文字 ≥ 半径+1.5
- **同时**要检查“标记之间”是否重叠（两个电荷圈叠在一起等）
- 对大椭圆（轨道瓣）**排除**，否则全是误报（本次第一版就误报了 18 幅）

## P1-2 示意性元件（箭头/方括号/弯曲箭头）必须验「方向与落点」

**症状**：
- fig2-12 的“孤对→键”箭头画成了“键→孤对”（方向反）
- 另一根箭头头部指到环心，离目标碳 5.6 单位
- fig6-1 的顺旋/对旋旋转箭头用 `<curve>` 画的，不是 `<arrow>`

**建议**：
- 箭头一律用 `<arrow>`（弧线带 `Center3D`），**不要用 curve 假装箭头**
- 校验：每根箭头**头部**到目标原子/键中点 ≤ 2 单位；尾部在电子来源处
- 弯曲箭头要判旋转方向（顺旋/对旋），不能只判“有没有”

## P1-3 重出图要幂等；改 PNG 必须回写 CDXML

**症状**：我直接在 PNG 上补点，CDXML 没同步 → 下次重渲染，修复丢失。更严重的一次：用「整块贴回」的方式改 PNG，**把 C 字母和部分键一起涂掉了**。

**建议**：
- 任何 PNG 修补都必须同步 CDXML，否则记入 `render_source: patch` 并在审计里降级
- 改 PNG 的正确姿势：**只在目标半径内涂白 + 重绘**，禁止整块区域 paste
- 提供“改完自动比对”的小工具：改前/改后墨迹差异必须只落在声明区域内

## P2-1 审计表要有固定 schema + 「不许变差」闸门

**症状**：某轮把 `audit/summary.csv` 表头从 `fig,verdict,basis,note` 换成 `fig,chapter,verdict,shown,missing,note,basis`，只填自己那几幅的 basis，其余行的 OK 没继承 → **OK 数从 51 掉到 34**，之后每轮都在更差的基线上重建。

**建议**：
- schema 固定，加版本号；改 schema 必须写迁移脚本
- 每轮结束做「OK 数不许下降」校验；下降即判该轮 FAIL 并回滚
- 同一思路再加一条「产物文件数不许下降」（本次另外踩过：某轮从 84 张 PNG 掉到 51 张）

## P2-2 静默失败清单（exit 0 但没干活）

本次实测到的：
1. `worktree add` 因目录已存在/分支被占用而失败，脚本继续跑 → 后面所有路径都不存在
2. `SaveAs` 到不支持的格式（pdf）→ 无异常、无文件
3. 审图脚本没拿到「声明产物清单」→ 去扫了 `docs/` 里的对照图，于是对着“过程图”判 pass
4. 日志用 `Tee-Object` 写成 UTF-16，用 UTF-8 读 → 标记永远匹配不上（等了 2 小时）

**建议**：每个“外部调用”后面都要断言「产物存在且非空」，不信退出码。

## 一句话给维护者

这批图最贵的教训不是“画不好”，而是**验证链断在了最不起眼的地方**：
回读通过 ≠ 渲染正确；审图通过 ≠ 产物正确；exit 0 ≠ 干过活。

把这三条做成机检，比再调十轮 prompt 都值。
